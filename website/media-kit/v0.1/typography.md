# 字体规范 v0.1.1（账簿 Ledger）

原则不变：系统字体栈，零 webfont 下载（性能与可复现）；代码与哈希一律等宽。
账簿方向在此之上加一条 —— **数字一律 `tabular-nums`**，因为账目要能按位比对。

| 用途 | 栈 |
|---|---|
| 正文/UI | `-apple-system, BlinkMacSystemFont, "Segoe UI", "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei", Roboto, Arial, sans-serif` |
| 代码/哈希/徽章/数字/表头 | `ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", monospace` |

## 等宽的使用边界

等宽在账簿里是**功能性**字体，不是风格装饰。固定落在这些位置：

表头、状态丸、kicker、面包屑、页脚小标题、环境条、所有数字与哈希、代码块、键值表的值列。

正文、标题、导语一律用系统无衬线 —— 长文用等宽会毁掉可读性。

## 排版纪律

1. 正文对比度 ≥ 4.5:1；品牌线实际按 **≥ 5.2:1** 卡（两套底各自实测，见 `colors.md`）。
2. 中英混排不加人工空格工具链约束，但宣传物料统一"中文与英文/数字之间留半角空格"。
3. 哈希、命令、域标签永不换行折断（等宽 + 横向滚动）。窄屏（≤720）例外：
   长标识符允许 `overflow-wrap: anywhere` 断行，否则整页会被撑出视口。
4. 不使用描边字、发光字；强调用颜色变量，不用字体变形。
5. **不用字重当层级**：账簿的层级由规线、3px 左规线、等宽大写小字、印章表达。
   标题固定 700/800，正文 400，不加中间档。
6. 数字列由 `build.py` 判定"整列都是量"时自动挂 `class="num"` → 贴右等宽；
   标识符列（`0x…` 哈希、含省略号的地址）留在左对齐 —— 它们是被查的键，不是被加的数。
7. 首屏大标题一律 `text-wrap: balance`。中文没有空格分词，15 字的标题在 1280 下
   会自然折出「…结算记 / 录。」这种把词和句号甩成孤行的断法；账簿版面不允许孤字行。
   只对 `h1`/`h2` 开，正文长段落不开（balance 会牺牲行尾密度）。
