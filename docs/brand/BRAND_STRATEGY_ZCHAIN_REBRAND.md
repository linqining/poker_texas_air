# ZChain 多游戏品牌重塑方案

> 版本：2026-09-27 / strategy draft v1  
> 命名复审：**UNRIG 已降级为 campaign 语汇，暂不作为最终母品牌**  
> 当前母品牌候选：**ProofPlay / 明局（待清查与测试）**  
> 品牌核心句：**The game proves itself. / 游戏自己证明公平。**

> 本文的视觉和产品架构仍以 UNRIG 作为 v1 占位示例；名称确认后，应统一替换为最终品牌锁定式。

## 0. 结论先行

ZChain 的问题不是技术不够强，而是名字无法让用户猜到它解决什么问题。Z 没有稳定联想，Chain 把品牌锁在基础设施和 Web3 语境，Poker 又把未来空间锁在单一游戏。

建议采用一个面向玩家和合作方的母品牌：

- **UNRIG / 明局**：可验证游戏平台；
- **UNRIG Poker / 明局扑克**：首发扑克产品；
- **UNRIG Proof**：玩家查看和复验每局证据；
- **UNRIG Protocol**：协议、合约、证明系统与白牌授权。

后续可以自然扩展为 UNRIG Blackjack、UNRIG Cards、UNRIG Arena。ZChain 保留为代码、chain id 和内部迁移名，不再作为公开母品牌。

### 命名复审 v2（2026-09-27）

反馈显示 UNRIG 的英文语感偏俚语、偏负向，也要求用户先理解 rigged，不适合直接作为长期母品牌。新的决策原则是“正向名词 + 可验证语义”，而不是“反向动词 + 反作弊情绪”。

当前建议：

1. **ProofPlay / 明局**：最容易让国际用户理解“游戏 + 证明”，正向且可扩展，但需要重点清查同名产品与域名。
2. **明局 / MINGJU**：中文语义最完整；英文可配 descriptor “Verified Games”，适合中文市场优先的策略。
3. **OpenRound**：正向、跨游戏、适合 Every round, proven 的传播，但独占性偏弱。
4. **Verity**：更高级、安静、适合协议与游戏平台，但“游戏”联想需要靠产品名补足。

UNRIG 保留为活动语汇，例如中文的“不设局，只开局”，不再作为母品牌结论。

## 1. 现状诊断

### 1.1 项目真正的品牌资产

项目最强的资产不是“有一条链”，而是玩家可以感知的四个结果：

| 能力 | 玩家语言 | 品牌价值 |
|---|---|---|
| 联合加密洗牌 | 运营方看不到牌，也不能叠牌 | 公平不是承诺 |
| 每步证明、可复验 | 每局都有证据，任何人可以检查 | 结果可追溯 |
| 私密资金路径 | 牌面和领取关系不必公开 | 隐私有边界 |
| 交互路径低延迟 | 密码学不让下注和出牌变慢 | 技术隐于体验 |

这四项支持一个比“区块链扑克”更大的品类：

> **Verifiable Games / 可验证游戏**：不要求玩家相信平台，而是让游戏运行过程留下可复验的证据。

### 1.2 当前品牌的问题

**名称**：ZChain 没有语义锚点，口头传播后难以回忆和拼写；Chain 会把普通玩家挡在门外；Poker 不适合继续承担母品牌边界。

**标志**：当前 Z、绿色牌毡和金色方块能够解释现有名称，却不能表达“游戏自己证明公平”。一旦不用 Z，图形含义就会断裂。

**视觉**：现有 Ledger 体系严谨、可审计、对比度高，适合文档、验证器和结算记录，但整套系统偏后台，缺少游戏品牌的张力、节奏和记忆点。建议保留它的证据语言，不要把整个玩家体验做成财务账簿。

**叙事**：仓库根目录 README 已描述 2026-09-07 后的 Starknet 主网运行状态，官网内容仍有 devnet / custodial v1 / 工作名的旧叙事。品牌以“可验证”为核心时，这种不同步会直接损伤信任。

重塑前需统一当前网络、链上与浏览器验证边界、资金退出状态、审计状态和路线图。

## 2. 品类、定位和品牌平台

### 2.1 品类

不是 Crypto casino、链游平台、扑克 Appchain 或 ZK 技术展示，而是：

> 一个以密码学证据代替庄家信用的可验证游戏平台。

### 2.2 核心人群

1. 关心平台会不会控牌、看牌、改结果的核心玩家；
2. 关心速度、资金退出、历史记录和复验的高价值扑克玩家；
3. 需要可信差异化、透明结算和白牌技术栈的运营方；
4. 关心协议、证明覆盖和威胁模型的开发者与审计者；
5. 加密用户是早期渠道，但不应决定全部品牌语言。

### 2.3 定位陈述

> 对于不愿再猜“平台有没有做手脚”的玩家，UNRIG 是一个可验证游戏平台。它让洗牌、关键动作与结算产生可复验的证据，因此公平不依赖庄家声誉；与只展示 RNG 证书或事后审计的平台不同，UNRIG 把运营方从牌局的信任闭环中移除。

英文版：

> For players who are done wondering whether the house is rigged, UNRIG is a verifiable game network where every round leaves evidence the player can check. Fairness comes from the game proving itself, not from trusting the operator.

### 2.4 品牌承诺

**游戏自己证明公平。**

它能被普通玩家理解，覆盖扑克以外的回合制和牌类游戏，也能落到真实动作：查看证据、验证一局、下载证明。

### 2.5 品牌人格

- 冷静的挑战者：质疑行业默认信任，但不靠恐惧营销；
- 精确的裁判：区分已证明、可复验和路线图；
- 克制的玩家：懂牌局、胜负和节奏，不像一份论文；
- 公开的建造者：用事实、版本和证据说话。

主原型是 Rebel / 挑战者，副原型是 Sage / 求真者。

## 3. 命名策略

### 3.1 原则

名字必须能联想到公平、规则、证据或反作弊；不包含 chain、zk、crypto 等技术周期词；可以连接多个游戏；英文易读易拼；同时服务 B2C 和 B2B；不暗示收益、胜率或绝对无风险。

### 3.2 候选路线

| 路线 | 候选 | 联想 | 优点 | 风险 |
|---|---|---|---|---|
| 挑战者 | **UNRIG / 明局** | 拆掉暗箱与操控 | 记忆最强、传播句天然、跨游戏 | 反向词，语气较锋利 |
| 信任机构 | **PROOF HOUSE / 证明之屋** | 庄家必须出示证明 | B2B 稳、游戏平台联想清晰 | House 仍有庄家中心感，ProofHouse.com 已注册 |
| 开放规则 | **OPEN ROUND / 明局** | 每回合公开可验 | 正向、亲和、可扩展 | 识别度和独占性较弱 |

### 3.3 决策矩阵

评分 1–5，按即时联想 25%、记忆与口播 20%、多游戏扩展 20%、玩家张力 15%、B2B 可信度 10%、国际化 10% 加权：

| 指标 | UNRIG | PROOF HOUSE | OPEN ROUND |
|---|---:|---:|---:|
| 加权结果 | **4.7** | 4.1 | 3.6 |

### 3.4 推荐名称：UNRIG / 明局

UNRIG 直接击中玩家最深的不安：游戏是否被操控。它不是“公平”“真实”“信任”的空泛形容词，而是一个动作：把暗箱拆掉。

中文建议用 **明局**，而不是生硬音译：

- “明”代表透明、明证、明牌，但不等于公开玩家秘密；
- “局”覆盖一手牌、一回合、一场游戏；
- “不设局”可以成为中文传播母题。

推荐组合：

~~~text
UNRIG
明局
The game proves itself.
游戏自己证明公平。
~~~

截至 2026-09-27 的初步网络筛查中，unrig.com 已被注册；搜索结果未显示一个明显占据“可验证游戏平台”定位的同名头部品牌。这只用于方向筛选，不等于商标或域名可注册。

定名前必须完成中国第 9 / 41 / 42 类、美国/欧盟/英国目标地区商标检索，以及应用商店、Steam、社媒账号、域名和母语负面语义检查。若无法通过，不要回到 ZChain，应继续沿“反暗箱 / 每局有证”语义造词。

## 4. 品牌架构

采用 Branded House / 单一母品牌：

~~~text
UNRIG / 明局              母品牌
├── UNRIG Poker            首发游戏
├── UNRIG Blackjack        未来牌桌游戏
├── UNRIG Cards            未来牌类合集
├── UNRIG Arena            未来竞技 / 技能游戏
├── UNRIG Proof            玩家验证与局记录
├── UNRIG Wallet           资金与身份工具
└── UNRIG Protocol         协议、SDK、白牌授权
~~~

命名规则：

- 玩家产品：UNRIG + 游戏品类；
- 功能产品：UNRIG + 功能名词；
- Mainnet、Testnet、Devnet 只做环境标签，不进入主标志；
- ZChain 只作为历史工作名和内部迁移映射，不创建新对外资产。

URL 使用统一品牌域名和路径结构：

~~~text
brand-domain.tld/poker
brand-domain.tld/proof/{round-id}
docs.brand-domain.tld
status.brand-domain.tld
~~~

不把 stark、chain、zk 写入主域名；底层技术会变化，品牌承诺不应变化。

## 5. 语言系统

### 5.1 主传播语

~~~text
The game proves itself.
游戏自己证明公平。
~~~

扑克产品：

~~~text
Don't trust the deal. Verify it.
不信发牌，验证每一手。
~~~

Proof 产品：

~~~text
Every round, proven.
每一局，都有证。
~~~

品牌活动：

~~~text
不设局，只开局。
~~~

活动语适合传播，不作为技术或法务声明。

### 5.2 一句话介绍

玩家版：明局是一个让游戏自己证明公平的平台。牌面保持私密，洗牌和结算留下证据，任何玩家都可以复验。

合作方版：UNRIG provides a verifiable-game stack for operators: encrypted game state, provable transitions, auditable settlement, and player-facing verification.

技术版：UNRIG combines mental-poker cryptography, client verification, formal specifications, and on-chain settlement checks to reduce the operator trust surface of online games.

### 5.3 文案纪律

| 要 | 不要 |
|---|---|
| 先说玩家问题，再解释证据 | 第一屏先讲 Appchain、STARK、EC_OP |
| 给出可点击、可下载、可验证的事实 | 只堆“公平、安全、透明” |
| 明确已上线、可复验和路线图 | 把可复验写成已链上强制 |
| 使用短句和主动语态 | 使用白皮书式长句 |
| 说“运营方不能看到或叠牌” | 泛化成“任何作弊数学上都不可能” |

所有营销声明分四级：L1 产品事实；L2 威胁模型覆盖的系统性质；L3 带日期和合约的网络状态；L4 绝对性主张默认禁用，除非明确限定攻击面。

## 6. 视觉识别方向

### 6.1 核心创意：Open Proof Mark / 开放证印

母品牌符号不使用 Z、链环或扑克花色，改由三层含义构成：

1. 开放的环：游戏不是黑箱；
2. 一对验证括号：规则和状态被约束；
3. 落下的证据点：每个动作进入可复验记录。

标志必须在 16–24 px、单色、打印和 favicon 中成立。扑克花色只进入 UNRIG Poker 产品图标。

### 6.2 标志原则

- 主标志：开放证印 + UNRIG 定制字标；
- 中文组合：英文主标在上或左，明局为正式中文名；
- 不使用盾牌：避免泛安全产品陈词滥调；
- 不使用链环：避免再次被理解为基础设施项目；
- 不把扑克牌放进母品牌；
- 不用渐变发光作为识别核心。

### 6.3 色彩

| Token | 色值 | 作用 |
|---|---|---|
| Proof Ink | #101512 | 主背景、标题、深色界面 |
| Paper | #F3F0E7 | 文档、证明收据、浅色界面 |
| Verify Green | #18A66A | 验证成功、主行动、品牌识别 |
| Signal Blue | #4967F2 | 交互、链接、实时事件 |
| Evidence Gold | #D49A2A | 资金、结算完成、稀缺强调 |
| Risk Red | #C64C42 | 错误、警告、证明失败 |

现有纸白、墨黑、毡布绿和账格线可以继续使用，但绿色从“扑克毡布”升级为所有游戏共用的验证成功色；金色仍只用于真实资金和最终结算。

每个游戏只增加一个辅助色：Poker 深酒红 #8D2F45；Blackjack 夜蓝 #244B74；Cards 紫罗兰 #6A4EC2；Arena 电橙 #E06B32。

### 6.4 字体与图形

- UNRIG 字标用定制几何字形，不依赖商业字体；
- UI、官网正文继续使用系统无衬线，保留零 webfont 性能优势；
- 哈希、局号、金额、证明状态用等宽字体和 tabular numbers；
- 保留 Ledger 体系，但把它收缩为证据层；
- 关键组件是 Proof Strip、Round Receipt、Evidence Blocks、Open Seal；
- 用 Secret / Public 双层表达“秘密不公开，正确性可公开”。

### 6.5 动效

动作发生：证据块进入 Proof Strip；客户端验证：outline 变为实心绿；回合完成：开放证印闭合 120–180 ms；证明失败：保持断开并指出原因。不做无意义发光、抖动和滚动动画。

## 7. 产品体验落地

### 7.1 首页首屏

~~~text
UNRIG Poker
不信发牌，验证每一手。

牌面加密，玩家共同洗牌，每一步证明实时验证。
运营方看不到你的牌，也不能叠牌。

[开始游戏] [验证一手牌]
~~~

技术架构、性能和协议细节放到后面，不让 Appchain 成为第一认知。

### 7.2 牌桌

- 默认只显示轻量状态：Shuffle verified · 8/8；
- 点击展开后进入完整 Proof Strip；
- 牌桌中心使用 UNRIG Poker 标识，母品牌证印保持低对比；
- 每手结束显示 View round receipt，而不是让普通玩家读哈希列表。

### 7.3 UNRIG Proof

输入 hand id、tx hash 或分享链接后，先给出 Verified / Incomplete / Failed，再按步骤展开证据，并明确客户端验证、链上验证和尚未链上验证的区别。支持导出 JSON、CLI 命令和可分享图片。

### 7.4 Round Receipt

把“每局可验证”变成可传播资产：

~~~text
ROUND #10482
UNRIG Poker

Shuffle       VERIFIED
Private deal  VERIFIED
Actions       BOUND
Settlement    VERIFIED ON STARKNET

Verify independently → /proof/10482
~~~

### 8.1 内容漏斗

| 层 | 用户问题 | 内容 |
|---|---|---|
| 认知 | “线上牌局会不会控牌？” | 反暗箱短视频、对比图、互动验证 |
| 理解 | “你们凭什么？” | 60 秒一手牌证据流程、Round Receipt |
| 信任 | “证明覆盖什么？” | 威胁模型、部署事实、教程、审计记录 |

### 8.2 发布活动

**不设局，只开局。**

发布片展示传统平台要求玩家相信黑箱，而 UNRIG 让每一步留下证据；互动页让用户拖动时间轴，看一手牌如何从秘密状态变成可验证结果；社交模板使用 I verified round #____。

每个技术声明链接到可复验证据或规范；每个网络状态声明带日期和环境；协议升级必须同步更新 Proof UI、文档和营销素材；不使用收益、财富自由或赌场稳赢叙事。

## 9. 迁移路线

### Phase 0：事实统一（1 周）

指定唯一对外事实源；对齐 README、官网、媒体包、状态页和法务页；建立声明分级表；暂停继续制作 ZChain 新物料。

### Phase 1：名称验证（2 周）

完成商标与域名清查；对 8–12 名目标玩家做口播、拼写和联想测试；访谈 5–8 名运营方/投资人；决定中英文名称和域名。

### Phase 2：识别系统（2–3 周）

完成母标志、中文组合、产品锁定式、浅色/深色/单色/favicon；固化 token、Proof Strip、Round Receipt；建立 Figma / CSS / SVG 单一源。

### Phase 3：关键触点（3–4 周）

替换官网首页、Proof 入口、牌桌标志、验证状态、局收据、文档、GitHub、视频、社交模板和白牌 one-pager。

### Phase 4：发布与验证（2 周）

发布 “ZChain Poker is becoming UNRIG Poker” 迁移公告；旧域名 301 和旧名称搜索承接；监测品牌搜索、直接访问、验证入口使用率和玩家理解度；30 天后复盘。

## 11. 立即执行清单

1. 暂定使用 UNRIG / 明局做内部原型，不立刻公开改名；
2. 先解决官网与 README 的网络状态口径冲突；
3. 对 UNRIG 完成商标、域名和应用商店清查；
4. 用首页首屏和 Round Receipt 做可点击原型；

6. 通过后再替换标志与品牌名，代码仓库和协议标识分阶段迁移。

## 12. 最终建议

不要把品牌继续建立在某项技术上，也不要寻找另一个没有含义的五字母造词。项目已经拥有一个足够强的用户问题：**玩家不应该相信庄家。**

UNRIG / 明局把这个问题变成品牌动作；“The game proves itself / 游戏自己证明公平”把复杂协议变成用户承诺；UNRIG Poker → UNRIG Proof → UNRIG Protocol 给未来多游戏和 B2B 授权留下完整空间。

现有 Ledger 视觉不是废案。它应从“整个品牌长什么样”收缩为“证据长什么样”，成为 UNRIG 最独特、最可信的产品界面资产。
